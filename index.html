Two trails for two different needs

Trail A uses Canvas page HTML for accessible, non-graded content and practice. In the workflow shown here, Canvas strips scripts and style blocks, so the code needs to fit the allowed HTML and use inline styles. Trail B packages JavaScript activities for complex interactions, reuse, or gradebook reporting.

Quick rule: Use Trail A when HTML and CSS are enough and no activity score is needed. Use Trail B when the interaction needs JavaScript, must report a grade, or will be reused across courses. Choose the package based on how it tracks completion or score.

Key gradebook distinction

Trail A and Trail B package options

Compare where each activity runs, what it can report, and what the team needs to maintain.

Trail A · Canvas page

Use Canvas-allowed HTML with inline styles. Canvas strips scripts and style blocks in this workflow, so interactivity stays within HTML/CSS. Fast to build and edit in place, no external hosting, and no gradebook score from the activity. Repeated inline styles need updates on each page.

HTML/CSS · ungraded

Trail B · Native SCORM

Zip the HTML activity with an imsmanifest.xml file and its multimedia/caption assets. This is the route in the deck for custom completion, percentage scores, retries, and higher-score logic. Revisions require repackaging and re-uploading.

Custom score reporting

Trail B · Rise Code block

Zip the HTML and assets with index.html at the ZIP root, upload the project to a Rise Code block, then publish Rise as SCORM. In the demonstrated workflow, Canvas receives completion based on viewing the lesson/slide. Rise’s code-block completion signal supports Continue blocks; it is not the custom code’s percentage score.

Completion tracking

Trail B · Storyline Web Object

Import the unzipped HTML project folder, with index.htm or index.html and its assets together, as a Web Object. Then publish the Storyline course as SCORM. In the demonstrated workflow, viewing the slide reports completion. A custom percentage needs an explicit connection to Storyline’s tracked result or a native SCORM package.

Completion or bridged score

Consistency and upkeep: Canvas page code can match the course but repeated styles are maintained page by page. Articulate templates and shared prompts can help keep package designs consistent. Articulate packaging requires a license and tool skills. Any reused package needs a Canvas check in each course.

Accessibility: Semantic HTML supports structured Canvas content. Custom code in any package still needs manual accessibility testing.
